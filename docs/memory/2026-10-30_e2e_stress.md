# 2026-10-30 E2E 压测首轮结论

## 任务

新增 `backend/tests/e2e_stress_test.py`：通过 Java 网关（8080）串行发起 20 个
自然语言请求，覆盖单表统计、多表合并、复杂时间差、显式图表、模糊口语五类，
采集 RT、HTTP 状态、响应结构完整性、AI 重试/警告与关键数值口径。

运行方式：

```bash
cd backend && ../.venv/bin/python tests/e2e_stress_test.py
../.venv/bin/python tests/e2e_stress_test.py --only 6,7,14 --no-download-check
```

## 首轮结果（2026-10-30）

- 通过 15/20（75%）；RT 平均 6.86s、中位 7.12s、P95 8.56s、最大 9.90s。
- Excel/Word 下载 URL 20/20 可下载。
- 12/20 触发 AI 重试，共多调用 16 次；首次错误全部是
  `代码必须在模块顶层给 result_df 赋值`。
- 失败归因：数据口径 4 个（#6/#7/#9/#16），饼图意图 1 个（#14）。

## 根因与建议

1. **重复上传件导致多表汇总金额翻倍（最严重）**
   - 目录内 8 张同构表（A/B/C 各有多份副本）被同时 concat，费用从正确的
     196255.21 放大到 550972.81；`单号.nunique()` 又掩盖了行数重复。
   - 建议在 `backend/app/services/table_catalog.py` 的 `_build_homogeneous_groups`
     按文件内容哈希去重，或只把 manifest `concat_tables` 声明的事实表放进组；
     上传索引应识别与已有文件内容相同的副本。
2. **`result_df` 必须位于模块顶层的校验与空数据规则冲突**
   - 模型为满足“空数据也要返回带列 DataFrame”，写成 `if/else` 分支赋值，
     被 `code_safety._has_top_level_result_assignment` 拒绝，白付一次模型调用。
   - 建议允许模块级 `If/Try` 分支内的赋值，或在生成 Prompt 中给出同时兼容
     顶层赋值与空值处理的代码模板。
3. **显式饼图被降级**
   - 模型返回“工单量 + 占比”两个数值列，`chart_meta` 规定饼图仅支持单数值列，
     于是降级为柱状图。建议显式 `pie` 请求时取第一个数值列，或让代码生成只
     输出一个数值列。
4. **`TABLE_MAX_FILES=8` 静默丢表**
   - 目录有 9 个 xlsx，只扫描前 8 个，仅给警告。建议按上传时间淘汰/报错，
     而不是按文件名截断。
5. **时间意图兜底为“全量区间”**
   - 10/20 未识别到显式时间，默认汇总目录全区间；数据跨月时会放大口径。
     建议对“最近/近期”等模糊词给固定窗口（如近 30 天）并显式提示。
6. **时间类指标覆盖率低**
   - 源数据 919 单仅 280 单有完成时间，平均时长类结果只覆盖 31%，但响应未提示
     样本缺失。建议在 `code_executor` 或 Agent 层对关键列空值率给出警告。

## 修复后回归（2026-10-30）

已落地的修复：

1. `table_catalog.py`：新增按 MD5 内容哈希去重（带 mtime/size 缓存），重复副本
   只保留 manifest 原始表；每个重复组只产出一条聚合警告。
2. `code_safety.py`：模块级 `if/else`、`try/except`、`with` 分支内的 `result_df`
   赋值均放行；函数体内赋值仍然拒绝。
3. `chart_meta.py`：显式要求饼图时取第一个数值列，不再降级为柱状图。
4. `config.py`：`TABLE_MAX_FILES` 默认 8→50（上限 200），超限写 WARNING 日志。
5. `code_query_agent.py`：时间差类问题若完成时间缺失占比 ≥20%，追加
   `meta.warnings`：“当前时间差指标仅基于已完成的 X 条工单计算，存在样本缺失”。

回归结果（全量 20 例，两次运行）：

| 指标 | 首轮 | 修复后 |
| --- | --- | --- |
| 通过率 | 15/20（75%） | 20/20（100%） |
| 平均 RT | 6.86s | 4.57s |
| P95 RT | 8.56s | 5.42s |
| 触发 AI 重试 | 12/20（60%） | 0~1/20（≤5%） |

- 数据表 3 张（A 420 / B 360 / C 139），重复副本按内容哈希跳过。
- 多表合并口径正确：919 单 / 196255.21；紧急工单 777 / 18033.53 / 均值 23.21。
- 显式图表 4/4 满足；`#14` 返回 `pie`，`y=["工单量"]`（占比列不再干扰）。
- 时间差 3 个请求均带样本缺失警告（280 条已完成）。
- 两次全量运行中重试为 0/20 与 1/20；后者是模型偶发把 `dtype=object`
  写成 `object`（`NameError`），由自修复链路一次纠正，与校验器无关。
- 遗留观察：#17 “哪个小区最闹心”模型返回枢轴形态（总工单量 / 工单最多小区 /
  该小区工单量 / 小区数量），内容正确，测试断言已放宽为“项目或小区 + 331 单”；
  口语时间词仍会兜底为全量区间，属已知边界。
